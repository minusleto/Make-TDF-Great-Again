# Kazakhstan maintenance (TDF repository)

Статус: действующие проектные соглашения и накопленные заметки только для Казахстана (`KAZ`), обновляемые по мере работы; это не универсальная спецификация HOI4. Примеры и фактологические сведения нужно перепроверять по актуальным файлам, brief, wiki и источникам. При конфликте сверять данные и сообщать о расхождении.

## 1. Структура дерева и формат

- В `mdredux/common/national_focus/Kazakhstan_Focus_Tree.txt` ставить короткий английский комментарий `#English Focus Name` перед каждым **новым или редактируемым** блоком фокуса. Использовать фактическое английское название из локализации, когда оно доступно. Не требуется массово добавлять комментарии к существующим legacy-блокам, где их сейчас нет; делать это только по отдельной задаче.
- Для новых и редактируемых блоков комментарий служит разделителем. Не оставлять пустую строку между закрывающей скобкой изменённого фокуса и следующим комментарием, но не переписывать соседние нетронутые блоки ради одинакового оформления.
- В новых и редактируемых блоках использовать табы. В существующем дереве есть исторические пробельные отступы: не конвертировать их массово; при точечной правке сохранять формат нетронутых строк, а отступы менять только внутри затрагиваемого блока.
- Различать порядок блоков в исходнике, расположение в игровом дереве и игровые prerequisite. Перемещение блока не должно незаметно менять `prerequisite` или `relative_position_id`.
- Корни веток сохраняют предполагаемого родителя. В воздушной ветке `KAZ_decommission_old_planes` привязан к `KAZ_our_military_forces` через `relative_position_id` и `prerequisite`; потомки остаются относительно корня воздушной ветки, если пользователь явно не просит изменить layout.
- Ключи локализации военных фокусов группировать в порядке веток: сначала Army в порядке фокусов, затем Air Force, затем Navy. Соответствующие определения национальных идей располагать в порядке прогрессии; `KAZ_trained_officer_corps_idea` — после `KAZ_modern_air_forces`.

## 2. Безопасность точечных правок

- Перед переименованием ID найти и обновить все ссылки по репозиторию: дерево, локализацию, prerequisites, `available`/`bypass`, события, идеи и scripted localisation. Не менять только определение и loc.
- В `l_english` сохранять заголовок `l_english:`, BOM и исходные окончания строк. Предпочитать точечные замены ключей; не пересобирать весь файл, если можно сохранить формат локально.
- Особый случай: в исследованном срезе `mdredux/events/Kazakhstan.txt` было 28 строк LF среди CRLF. Перед правкой проверить текущее состояние; сохранять исходные BOM и CRLF/LF, при поиске и заменах учитывать `\r?\n`, не нормализовать файл целиком.
- Для локальных правок читать актуальный файл и заменять только ожидаемый фрагмент. Для GitHub API сначала получить текущий blob SHA; если ожидаемый фрагмент не найден, остановиться, а не угадывать. После записи повторно получить файл и проверить порядок блоков, комментарии, ID, prerequisites, relative positions, ссылки локализации, BOM и окончания строк.
- При удалении или замене фокуса проследить всю цепочку наград: запущенные события и их продолжения, национальные духи/идеи, локализацию и другие ссылки. Удалять только подтверждённо осиротевший контент.
- Для KAZ-правок не считать статическую проверку игровым тестом. Не заявлять, что мод запускался или синтаксис проверен игрой, если это не так.

## 3. Исторические и технические заметки

Эти заметки — точки внимания из прошлых фактчеков. Перед тем как вставлять факт в новый текст, заново открыть надёжный источник и проверить формулировку и дату.

- KMC «Астана Моторс» — гражданская компания; не использовать её для военного ремонта или модернизации танков без отдельного подтверждения.
- 22-я бригада ГРУ СССР (Капчагай) перешла Казахстану после 1991 года; не называть её «казахстанским ГРУ» без уточнения происхождения.
- Airbus Helicopters Kazakhstan Engineering (AHKE) уже существует как совместное предприятие с Airbus; если речь о более позднем проекте, различать создание компании и её расширение.
- Реформа округов 2003 года: округа стали региональными командованиями. Для контрактной армии различать план (99%) и фактический уровень (около 65%).
- ВМС Казахстана, согласно заметкам поиска 2026-10, созданы указом 2003 года; главная база — Актау. Пограничную службу и её объекты (Баутино, Атырау) не смешивать с ВМС. В 1993 году Казахстану досталась примерно четверть патрульных катеров Каспийской флотилии; подлодок нет.
- Завод «Зенит» находится в Уральске на реке Урал, не на побережье; корабли достраиваются на Каспии. Тральщик «Алатау» (2016) построен российской верфью.
- Турция: в заметках отмечены соглашение «Зенита» с ASFAT и YDA о проектировании/постройке кораблей (2023), план верфи у порта Курык (2024, помечен как требующий проверки) и обучение казахстанских кадетов.
- Южная Корея: в заметках отмечены катера типа Chamsuri и исследовательское судно примерно в 2006 году. Германия: меморандум с Abeking & Rasmussen о корветах (2016), который не был исполнен.
- Китай и флот Казахстана: прежний поиск подтверждал заявку на постройку корабля (год не указан) и коммерческие контейнерные хабы CSIC (2023), но не военное-морское сотрудничество. Заметка о запрете присутствия вооружённых сил нерегиональных стран по Конвенции о статусе Каспия 2018 года ранее была помечена как не перепроверенная; не использовать без нового фактчека.
- Не помещать гражданские компании в военные фокусы без подтверждения; не хардкодить столицы и имена лидеров; не давать спойлеры поздних фокусов.

## 5. Известные технические вопросы

- В репозитории встречаются `add_daily_mastery` с папками `air`, `land` и `elite_forces`; вариант с папкой `naval` в доступном срезе не найден. Перед использованием проверить текущий репозиторий и базовый мод.
- Изменения нескольких файлов одной задачи объединять в один коммит, когда это технически возможно. Для GitHub Git Data API можно подготовить все изменённые blobs, один tree и один commit; не создавать отдельный коммит на каждый файл.
- После содержательной переработки KAZ обновить соответствующую заметку в `docs/research/` и перечислить неподтверждённое.

Общий баланс, стандарты описаний, типовые ошибки и итоговый чек-лист остаются в `references/balance-and-pitfalls.md`; здесь не дублировать их.
