# Дизайн фокуса и ветки

Все ссылки на код проверены по файлам репозитория на 2026-10-30. Синтаксис, помеченный [?], не подтверждён и требует проверки по wiki или в игре. Числовые нормы ниже — статистические ориентиры и решения команды, а не ограничения движка.

## 1. Скелет фокуса (порядок полей по Португалии)

```
	#English Focus Name
	focus = {
		id = TAG_focus_id
		icon = GFX_or_name_of_icon

		x = 0
		y = 1
		relative_position_id = TAG_parent

		cost = 5

		prerequisite = { focus = TAG_parent }
		search_filters = { FOCUS_FILTER_INDUSTRY }

		available = { ... }          # реальные игровые условия, не даты
		bypass = { ... }             # если цель могла исчезнуть или стать недостижимой

		completion_reward = {
			log = "[GetDateText]: [Root.GetName]: Focus TAG_focus_id"
			# 1) опыт и исследования, 2) инструмент (дух, событие, решение, флаг), 3) казна в конце
		}

		ai_will_do = {
			base = 50
		}
	}
```

Измеренные соглашения:
- `ai_will_do`: `base` в 8 деревьях, `factor` в Беларуси и Словакии (унаследовано от общего шаблона). Для новых деревьев - `base`.
- `cost`: медиана 5; в Армении, Беларуси и Словакии - 3. Для нового дерева брать 5, если команда не решит иначе.
- `log` в награде: формат `Focus ID` везде, кроме Армении и Израиля (`focus ID executed`). Id в логе должен совпадать с id фокуса: copy-paste этой строки самый частый баг (Венгрия 44, Словакия 37, Россия 36, Израиль 28, Польша 27).
- Перед каждым фокусом короткий английский комментарий `#English Focus Name`; он же разделитель блоков (правило Казахстана). Пустые строки между блоками не добавлять.
- Только табы. Пробелы вместо табов сейчас в Казахстане (824 строки) и Венгрии (749).

## 2. Как фокус даёт инструмент: проверенные шаблоны

### Фокус открывает пакет решений (Россия, `SOV_economic_rjd`)

В награде: флаг, tooltip будущего духа и подсказка про открытые решения.
```
completion_reward = {
	log = "[GetDateText]: [Root.GetName]: Focus SOV_economic_rjd"
	set_country_flag = SOV_rjd_idea_yes
	effect_tooltip = { add_ideas = SOV_rjd_idea }
	custom_effect_tooltip = {
		localization_key = UNLOCK_DECISION_IN_CATEGORY
		DECISION = SOV_economic_rjd_north_latitudinal
		DECISION_CATEGORY = SOV_kremlin_category
	}
}
```
Решения в категории открываются условием `visible = { has_idea = SOV_rjd_idea }`. Правило: каждое открытое решение надо показать игроку через `UNLOCK_DECISION_IN_CATEGORY` (или аналог), иначе фокус даёт "невидимый" инструмент. В этом фокусе `add_ideas` стоит внутри `effect_tooltip`, а он только показывает эффект: сам дух выдаётся другим эффектом по флагу, которого в репозитории нет [?]. Проверять до правки.

### Фокус меняет ступень духа-хаба (Португалия)

Проблема заменяется улучшенной версией, tooltip собирается scripted loc (см. `national-spirits.md`):
```
swap_ideas = { remove_idea = POR_last_centurys_infrastructure add_idea = POR_last_centurys_infrastructure1 }
```
Убрать идею, которой уже нет, - баг: проверять, что `remove_idea` выполнимо в момент награды.

### Цепочка предложение - ответ (дипломатия, закупки)

Подробный шаблон событий и AI: `skills/md-hoi4-country-content/references/code-patterns.md`. Кратко: фокус шлёт предложение партнёру (`PARTNER = { country_event = { id = ns.N days = 1 } }`), принятие шлёт ответ в `FROM`, отказ - общий ответ; реальный бонус выдаётся один раз. Условие в `available`: у партнёра есть технология или нужное мнение, нет войны.

### Фокус и флаг, который читает чужой контент

Израиль: решения проверяют флаги (149 условий `has_country_flag`). Правило: флаг, который никто не читает, - мусор. Сейчас "мёртвых" флагов, заданных в деревьях и не прочитанных нигде, больше всего в Беларуси (около 20), Армении (около 18) и России (около 60 из 66 заданных - часть, возможно, читается базовым модом).

## 3. Как строить ветку

Различать типы требований:
- **Обязательное техническое правило** — подтверждено кодом/движком или принято как соглашение формата проекта.
- **Рекомендация дизайна** — обычно улучшает читаемость или игровой выбор, но допускает исключения.
- **Статистический ориентир** — описывает текущие деревья, не задаёт целевую норму.
- **Решение команды** — действует для конкретной задачи или страны; при конфликте уточнять актуальное решение.

Не превращать статистику по десяти деревьям в автоматический запрет. Размер ветки, доля инструментальных фокусов и число модификаторов выбираются под масштаб и механику страны.

1. Ветка начинается с корня-обещания (id `TAG_<branch>`), который присоединён к родителю через `relative_position_id` и `prerequisite`. Корень ветки не должен висеть отдельно.
2. Порядок внутри ветки: проблема или цель, затем инструмент, затем развитие инструмента, затем капстоун. Каждый следующий фокус развивает тот же инструмент, а не добавляет похожий.
3. Развилки - реальные: `mutually_exclusive` или OR-prerequisite. Израиль использует `mutually_exclusive` в 124 фокусах (19%), Сирия в 56, Россия в 40, Беларусь в 2.
4. Гейты - игровые условия (партнёр владеет технологией, мнение, нет войны, завершён предыдущий фокус), а не даты: старт сценария может быть любым.
5. `bypass` ставить на фокусы, чья цель исчезает (страна-партнёр перестала существовать): `bypass = { NOT = { country_exists = PARTNER } }`, одним условием, без обёртки `OR = { ... }` вокруг одного `NOT` (так было у `KAZ_naval_coop_russia`: пустая обёртка). `country_exists` не дублировать в `available`: `bypass` пропускает фокус раньше, `available` остаётся для войны, мнения, технологии.
6. Альтернативные маршруты не заставлять проходить всё подряд; капстоун достижим без посторонней промышленной и дипломатической ветки.
7. Фокус, который игрок взять не может (`available = { always = no }`), допустим только как узел-показ (Россия, компании: 4 случая; Польша 6; Израиль 4); в дереве должно быть понятно, как он открывается.
8. Дипломатический фокус шлёт событие партнёру прямо из награды (`PARTNER = { country_event = { id = ns.N days = 1 } }`, одна строка) и показывает результат стандартным `custom_effect_tooltip = effect_if_they_accept_TT` + `effect_tooltip = { ... }` с эффектами события согласия. Подробности: `design-guide.md`, п. 3.3.
9. Здания и верфи. Правило: если в описании фокуса или события названо конкретное место (город, область), строить в нём готовым скриптом MDC в области штата: `1230 = { # Mangystau  two_state_dockyards = yes }` (есть `one_state_*` и `two_state_*` для верфей, заводов и других построек; стоимость списывает сам скрипт, см. `wiki/docs/code-resource/effects/buildings.md`), а условие ставить в `available = { controls_state = 1230 }`, не оборачивая награду в `if = { limit = { controls_state ... } }`. Если место в тексте не названо, использовать обычные `one_random_dockyard` / `two_random_dockyards`. Не собирать вручную `random_owned_controlled_state` + `add_building_construction` + `treasury_change`: так было в `KAZ_first_shipyards` (случайный штат мог оказаться внутренним, а -15 казны не совпадало с ценой скрипта).
10. Id фокуса: префикс страны заглавными, остальное строчными с `_`: `KAZ_first_shipyards`, не `KAZ_First_Shipyards` (в Израиле 0 id с заглавным словом, в Казахстане 20 из 351 - это legacy, не копировать). Id короткий, 2-4 слова: `KAZ_naval_coop_turkey`, не `KAZ_naval_cooperation_with_turkey`; страна словом (`russia`, `turkey`), не тегом. Для сделок с одной страной в дереве принято `KAZ_<что>_<страна>` (`KAZ_skylark_israel`, `KAZ_wing_loong_china`, `KAZ_t72kae_turkish`).
10a. Для сделки, где в игре нет подходящего оборудования, награда - тех-бонус и цена, а не выдуманная техника: `KAZ_wing_loong_china` дала бы MiG-29 (в фактчеке недоказано), поэтому там `add_tech_bonus` на `CAT_drones` и казна. Иконку, которую команда оставила, не менять (`buy_chinese_j7iii` у `KAZ_wing_loong_china` оставлена решением команды).
11. Перед каждым `focus = {` стоит комментарий с английским названием вместо пустой строки, сразу после закрывающей `\t}` предыдущего фокуса: `\t}` `\t#Naval Forces` `\tfocus = {`. Двойных и тройных пустых строк между фокусами не оставлять.
12. В `completion_reward` эффекты, которые списывают деньги (`one_random_dockyard`, `*_state_dockyard(s)`, `modify_treasury_effect`, любые постройки за казну), ставить в самый конец награды, после опыта, духов и остального. `newline = yes` перед ними не ставить (правило команды: только по прямой просьбе).
13. Тех-бонусы и очки доктрин: `add_tech_bonus` с одним `bonus` на несколько категорий пишется одним блоком (несколько строк `category = ...` подряд, при одинаковом бонусе); `name` - id фокуса (`name = KAZ_modernization_of_the_navy`), отдельный ключ локализации не заводить. Разовые очки доктрин - `add_mastery = { amount = 200 folder = naval }` (есть в вики, `name` не нужен), а не `add_daily_mastery` по дням; `add_daily_mastery` - только для длинного прироста, и его `name` обязан быть ключом локализации. Бонус 0.5 при 1 использовании - нормальный размер для одной награды, 0.1 слишком мало.
14. `navy_experience` / `army_experience` / `air_experience` не ставить в каждый фокус ветки как наполнитель. Опыт даётся там, где он по смыслу (обучение, инструкторы, учения, подготовка экипажей, обкатка доктрины); у верфей, модернизации, дипломатических фокусов и капстоуна опыта по умолчанию нет. Если у награды остаётся только эффект здания или смена духа, это нормально.
15. Не удалять существующие события и тексты без запроса команды: сначала спросить, зачем, и предложить исправление (так был зря удалён `kaz_army.4`, потом возвращён).
16. Техи и техника для дип-сделок: id теха совпадает с id оборудования (`util_vehicle_0…7` для многоцелевых машин `CAT_util`, `APC_1…8` для БТР `CAT_apc`, шаг 10 лет, `common/technologies/infantry.txt` и `armor.txt`). Если сделка выдаёт `set_technology = { X = 1 }`, у партнёра эта теха должна быть: `PARTNER = { has_tech = X }` в `available` фокуса. Машины идут `add_equipment_to_stockpile = { type = X amount = N producer = PARTNER }` в событии получателя (образец: Сирия, `util_vehicle_2`, 100 от США), а не выдуманным типом. Пример: `KAZ_arlan` (`util_vehicle_4`, 100 машин от ЮАР).
17. БТР и БМП (`medium_tank_amphibious_chassis_N` и `medium_tank_flame_chassis_N`) в других странах выдаются так: `create_equipment_variant` с `design_team = mio:...` и `allow_without_tech = yes` (образец: `TAIMAS 8x8`, `KTO Rosomak`, `BWP Borsuk`), машины `add_equipment_to_stockpile` с `variant_name`, и `add_tech_bonus` на `CAT_apc` или `CAT_ifv` (0.2-1.25). `set_technology = { APC_N = 1 }` и `mbt_tech_*` для них не выдавать: так теху получает только KAZ, а условие `has_tech` у партнёра запирает фокус на годы. Исключение: многоцелевые машины `util_vehicle_N` (п. 16).

## 4. Антипаттерны (с доказательствами из репозитория)

| Антипаттерн | Где видно | Что делать |
|---|---|---|
| Фокус - только числа | грубая автометрика: ISR 22%, POL 24%, ARM 32% фокусов с инструментом | слить с соседним или добавить инструмент |
| Чужая страна внутри дерева | Словакия: `POL_outdate_equipment`, `POL_soviet_defence_doctrine`; Венгрия: `POL_death_penalty_idea`; Португалия: 3 ссылки на `POL_` | писать идеи и флаги со своим префиксом |
| Копия `log` из соседнего фокуса | `SLO_army_modernization` логируется как `SLO_armed_forced` | править `log` при копировании |
| Нет описания | Казахстан: 73 `_desc` не найдено (27 из них - заглушки с пустой наградой) | писать `_desc` к каждому видимому фокусу; отключённые ветки (`allow_branch = { always = no }`, Польша: космос) не считаются |
| Фокус-заглушка | Казахстан: 31 фокус с наградой только `log` (`KAZ_neftprom`) | дать инструмент или убрать; не оставлять видимым |
| Дубль ключа loc | Казахстан 25, Польша 7, Венгрия 3 | один ключ - один раз |
| Фокус "создаёт" то, что уже есть | разбор Казахстана: AHKE уже существует | моделировать расширение, модернизацию, локализацию |
| Тот же бонус дважды (фокус, предложение, ответ) | `skills/md-hoi4-country-content/references/pitfalls.md` | бонус выдаётся один раз |
| Награда только внутри `effect_tooltip` | подозрения по автопроверке: POL 45, SLO 26, ISR 29 | реальный эффект вне `effect_tooltip` |
| Событие на ссылку вне репозитория | `CSTO.1`, `union_state.22`, `ukraine_coup.1` | проверить в базовом моде до правки |

## 5. Сколько фокусов нужно (позиция команды и предложение)

Позиция команды: меньше фокусов, но каждый с механикой. Сейчас в репозитории 180-667 фокусов на страну, глубина цепочек 8-13 (Россия 29 из-за мегадерева партий). Предложение для новых и переписываемых деревьев (ориентир, не измерено): сначала составить список инструментов страны (какие решения, духи-хабы, события с выбором, флаги будут), затем дать каждому инструменту фокус; фокус без инструмента вносить только как мост и не подряд.

## 6. Менее частые поля и приёмы (проверено по репозиторию)

| Поле или приём | Где используется | Как |
|---|---|---|
| `will_lead_to_war_with = TAG` | 57 фокусов (Россия 34, Сирия 13, Португалия 8, Израиль 2) | на фокусах, которые ведут к войне; вместе с `bypass`, если цель исчезла (`POR_attack_spain`: `bypass` для `SPR` пуппет, не существует, в одной фракции) |
| `allow_branch = { ... }` | 4 фокуса: Израиль (`NOT = { has_dlc = "By Blood Alone" }`), Польша (`always = no` скрывает космическую ветку) | скрыть ветку целиком по DLC или как отключённый контент; потомки скрываются вместе с корнем |
| `initial_show_position = { x y }` | Россия, Беларусь | куда смотрит камера при открытии дерева |
| `continuous_focus_position = { x y }` | все 10 деревьев | позиция палитры непрерывных фокусов |
| `shared_focus = ID` | 17 вхождений (`USoE001`, `POTEF001` и др.) | общие ветки мода (ЕС и т. п.), в дереве страны только подключаются |
| `hidden_effect = { ... }` | 346 вхождений | отложенные события (`country_event ... days = 250 random_days = 100`), смена партии, `news_event` |
| `show_ideas_tooltip = ID` | 96 вхождений (Россия 34) | показать идею в подсказке, не выдавая её; обычно вместе с `custom_effect_tooltip` |
| `has_completed_focus = ID` | 417 вхождений в деревьях | условие в `available` или `limit`; решения и события тоже читают завершённые фокусы |
| `search_filters` | везде | в репозитории `FOCUS_FILTER_*`; у Казахстана 237 токенов без префикса (`economy`) - проверить, определены ли они вне репозитория |
| иконки `icon = ...` | везде | `.gfx` и текстуры в репозиторий не входят: существование иконки не проверить, копировать из соседних фокусов |

Скрипт: фокусы в отключённых ветках (`allow_branch = { always = no }` и все, чьи prerequisite целиком из таких) в проверку локализации не попадают и выводятся как `hidden_branch_focus`.
