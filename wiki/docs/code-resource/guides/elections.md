Всё ниже — разбор `common/scripted_effects/00_subideology_scripted_effects.txt`, служебных эффектов, которые считают силу партий, проводят выборы и решают, с кем ИИ сформирует коалицию. Пригодится, если правите баланс партий, добавляете новую субидеологию или хотите понять, почему ИИ выбрал именно такую коалицию.

## Конвейер обновления

Три «мастер-эффекта» вызывают всё остальное по цепочке:

| Мастер-эффект | Когда вызывается | Что делает |
|---|---|---|
| `startup_politics` | Один раз при старте страны/игры | Полная инициализация: суммы партий → позиции → электоральный порог → мажоритарный порог → сила коалиции → название партии → топ-2 |
| `recalculate_party` | При любом изменении популярности партий (add_popularity и т.п.) | Лёгкий пересчёт: суммы → позиции → сила коалиции |
| `hold_elections` | На выборах | Полный электоральный пересчёт, включая проверку барьера прохождения и бан-флагов |
| `recalculate_party_strength` | Периодически (не выборы) | Как `hold_elections`, но без бан-флагов и без пересчёта топ-2 |

## Как субпартия делит вес идеологической группы

`add_up_party_totals` — сердце системы. Ключевая механика: каждая субидеология (`party_pop_array^0..23`) нормализуется **внутри своей идеологической группы** (democratic/communism/fascism/neutrality/nationalist — 0–3 / 4–9 / 10–11 / 12–19 / 20–23), а затем масштабируется на актуальную ванильную популярность этой группы (`party_popularity@democratic` и т.д. — тот самый бегунок из ванильного HOI4). То есть сумма всех субидеологий одной группы всегда равна ванильному проценту этой группы — двигать бегунок группы в эффектах бессмысленно, если не двигать процент конкретной субидеологии внутри неё.

Если у группы ванильная популярность >1%, а все её субидеологии почему-то дают в сумме <1% (несостыковка данных) — движок **случайно** раздаёт 1% одной из субидеологий группы (`random_list`, равные веса), лишь бы группа не осталась "невидимой" на графике. Шиитские субидеологии (8, 9) в этой лотерее исключены, если у страны нет `has_idea = shia`.

## Электоральный барьер и порог большинства

- `election_threshold` — по умолчанию **5%** (`setup_election_threshold`, если переменная ещё не установлена), меняется эффектом `modify_election_threshold`, зажат в диапазоне **0–10%**.
- Партии ниже барьера в `party_pop_elect_array` обнуляются — участвовать в выборах/коалиции не могут, даже если реально популярны в `party_pop_array`.
- `majority_threshold` = 50% от суммы **всех** электорально учтённых партий (`update_majority_threshold`) — пересчитывается каждый раз перед выборами.

## Порядок партий и топ-2

`set_party_positions` сортирует все 24 субидеологии по убыванию популярности и складывает индексы в `pos_array` (0 = самая популярная). `find_two_highest_parties` находит двух лидеров гонки (`max_index_1`, `max_index_2`) — именно они становятся «затравками» для формирования коалиции у ИИ (см. ниже).

## Бан партий — ловушка с нумерацией

⚠️ **Важно**: флаги бана партий **однобазовые** (`party1_banned` … `party24_banned`), а массив субидеологий **нольбазовый** (`party_pop_array^0` … `^23`). То есть:

| Флаг | Обнуляет индекс |
|---|---|
| `party1_banned` | `party_pop_elect_array^0` (Прозападные автократы) |
| `party2_banned` | `party_pop_elect_array^1` (Консерваторы) |
| ... | ... |
| `party24_banned` | `party_pop_elect_array^23` (Монархисты) |

Если ставите `set_country_flag = party12_banned`, чтобы забанить партию с `party_index = 12` (Умеренные исламисты) — это неправильно, флаг сработает на индексе 11 (Салафитский джихад). Нужный флаг — `party13_banned`.

## Стоимость приглашения партии в коалицию

`refund_government_coalition` считает политическую цену (в очках нац. управления) пригласить конкретную партию: для каждого текущего члена коалиции берётся политическая дистанция до кандидата (см. матрицу ниже), умножается на его вес и суммируется, итог умножается на **1500**.

## Как ИИ формирует коалицию

`AI_setup_government` строит **два** кандидатских варианта коалиции — вокруг лидера гонки (`max_index_1`) и вокруг второго места (`max_index_2`) — и выбирает более дешёвый:

1. `make_affinity_arrays` — для каждой из двух затравок считает политическую дистанцию до всех остальных партий (через матрицу ниже)
2. `reduce_affinity_array_party_1/2` — жадно добавляет в коалицию **самых близких** (наименьшая дистанция) кандидатов один за другим, пока сумма электоральных голосов не превысит `majority_threshold`; после первого превышения откатывает последнее добавление и одним финальным шагом добирает недостающее
3. Побеждает вариант с меньшей итоговой стоимостью (`cost1` vs `cost2`)

## Политическая дистанция между партиями

552 направленных значения (0.1 = почти союзники, 1.0 = максимально чужие). **Не симметрична** — из 276 уникальных пар только 138 значений совпадают в обе стороны, у большинства своя цена «пригласить» в одну сторону и в другую. Например: Военные (22) готовы звать Салафитский джихад (11) в коалицию почти задаром (0.2), а вот Салафитский джихад считает Военных предельно чуждыми (1.0) — обратной взаимности нет.

## Готовая утилита: сдвинуть популярность одной партии

`add_relative_party_popularity` — задокументированная в исходнике переиспользуемая функция, синтаксис:

```
set_temp_variable = { party_index = X }              # индекс партии, 0–23
set_temp_variable = { party_popularity_increase = Y } # доли, напр. 0.02 = +2%
set_temp_variable = { temp_outlook_increase = Z }     # необязательно, тоже доли
add_relative_party_popularity = yes
```

## Марионетки наследуют правящую партию сюзерена

`effect_puppet_match_ruling_party_to_overlord` (используется в скоупе марионетки, `FROM` = сюзерен) копирует правящую партию и коалицию сюзерена марионетке один в один, плюс проставляет country-флаг `set_<subideology>` под конкретную партию (например, `set_conservatism`, `set_Western_Autocracy`) — по нему, видимо, потом что-то может триггериться отдельно (ивенты про подчинение политике метрополии и т.п.).
